# AGENTS.md

Единственный источник правил для агентов в этом проекте.
`CLAUDE.md` и `.cursor/rules/000-project.mdc` только импортируют этот файл.
Копий не делать: расходящиеся копии дают агенту противоречия.

Продуктовые и архитектурные решения — в `BRIEF.md`.
План работ — в `TASKS.md`.
Если этот файл и `BRIEF.md` расходятся, побеждает `BRIEF.md`, и надо спросить.

## Проект

Веб-приложение: по артикулу Wildberries показывает фотографии карточки,
скачивает выбранные в zip и видео в mp4.

Стек: React 19, TypeScript strict, Vite, Mantine, TanStack Query, fflate.
Структура: FSD без слоя widgets.
Пакетный менеджер: pnpm.

## Команды

```
pnpm dev         запуск
pnpm lint        eslint
pnpm typecheck   tsc --noEmit
pnpm test        vitest
```

## Протокол задачи

Рабочая единица — первая незакрытая задача в `TASKS.md`.

1. Назвать номер задачи и её критерии готовности до начала работы.
2. Сделать только эту задачу.
3. Проверить каждый критерий.
4. Прогнать `pnpm lint` и `pnpm typecheck`.
5. Поставить `[x]` и одну строку в заметке.
6. Остановиться. Следующую задачу не брать.

Если решение неочевидно — остановиться и задать один вопрос:
что неясно, чем плохо решить неверно, какой вариант рекомендуешь и почему.
Молча выбирать вариант по умолчанию нельзя.

## Правила, закрытые проверками

Эти нарушения ловит линтер, tsc, тест или git-хук.

- `any` запрещён. Неизвестные данные — `unknown`, разбор явный.
- `as` для подавления ошибки типов запрещён.
- Не-null утверждение `!` запрещено.
- Неиспользуемые переменные и импорты запрещены.
- Индексный доступ считается возможно undefined (`noUncheckedIndexedAccess`).
- Тест на сборку ссылок из корзин CDN обязателен и должен проходить.
- `erasableSyntaxOnly` выключен: в проекте обязательны TypeScript `enum`.
- Код без `pnpm lint` и `pnpm typecheck` не коммитится. Закрыто хуками,
  а не договорённостью: pre-commit запускает lint-staged и
  `pnpm typecheck` на всём проекте.

## Правила, которые проверками не закрыть

Их соблюдение проверяется на ревью. Каждое сформулировано так,
чтобы можно было ответить да или нет.

**Структура**

- Файл лежит в слое по смыслу, а не по типу файла.
- Фича не импортирует файлы из внутренностей другой фичи.
- Компонент не вызывает fetch и не знает про адреса. Запросы в `entities`.
- Один экспортируемый компонент на файл.

**Состояние**

- Серверные данные живут в TanStack Query.
- Результат запроса не копируется в `useState`.
- Локальное состояние экрана остаётся в компоненте.
- Дискриминанты состояний и исходов — TypeScript `enum`, не строковые литералы.

**Чужой API**

- Диапазоны корзин CDN берутся живым запросом. Зашитый список допустим
  только как аварийный запас и обязательно с комментарием, зачем он.
- Любое поле чужого ответа считается ненадёжным. Количество фотографий
  не гарантирует, что все ссылки существуют.
- Ошибка сети видна пользователю. `console.log` обработкой не считается.
- Ключей и секретов в коде нет.

**Интерфейс**

- У каждого блока с данными есть все четыре состояния: загрузка, пусто,
  ошибка, успех.
- Ошибка даёт действие, а не только текст.
- Кнопка, чекбокс, модалка берутся из Mantine, а не пишутся руками.
- Экран проверен на ширине 375 пикселей.

**Производительность**

- Одновременных сетевых запросов не больше 6.
- Всё, что длится дольше секунды, показывает прогресс.
- Мемоизация только там, где эффект виден. Не оптимизировать до замеров.

## Коммиты

Одна задача — один коммит, после проверки критериев.

Формат: `тип(область): изменение в повелительном наклонении`

Типы: `feat` `fix` `refactor` `perf` `test` `chore` `docs`
Области: `api` `product` `product-media` `download` `ui` `ci`

Тема на английском, до 72 символов, без точки. Описывает изменение,
а не номер задачи.

Хорошо: `feat(product): build media urls from live cdn upstreams`
Плохо: `feat: complete T-4`

В теле — причина изменения и любое решение, которое читатель мог бы оспорить.
Если что-то сознательно не сделано, сказать что и почему.

Атрибуции инструментов нет. Ни `Generated-By`, ни `Co-Authored-By`,
ни упоминания агента в теме и теле. Кто запускает `git commit`,
тот отвечает за код.

## Запреты

- Не коммитить `.env`, ключи, `node_modules`.
- Не добавлять зависимость без явного упоминания в отчёте.
- Не смешивать рефакторинг и фичу в одном коммите.
- Не коммитить недоделанную задачу.
- Не править `BRIEF.md` и этот файл.
